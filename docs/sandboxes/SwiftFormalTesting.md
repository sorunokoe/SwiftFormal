# SwiftFormalTesting: Walk inside your tests

**Job (Inspector view):** the inspector's report card for a test run. It turns a failed proof into a test failure.
**Raw input → typed → result:** a `Domain` and a function (or a step over `.sessions(from:actions:upTo:)`, or an `ExitTestWalk` type) → `Prove`, the one way to walk: `Prove(it:over:)`, `Prove(it:)` for a `Finite` input, `Prove(it: step, over: .sessions(...))`, `await Prove(neverTraps:)` → a recorded test issue (known issues as `knownIssue:`) and a walk record for `swiftformal check`. The pre-release names (`expectProved`, `prove`, `expectNoTrap`, `walkInExitTest`, `lockBehavior`, `expectLocked`, `describeOutput`, `Table`, `Image`) are unavailable declarations that name their replacement; the trap walk's parts and the behaviour lock are `package` (its own tests use them). `OneWayToWalkSlowTests` builds a package that depends on SwiftFormal as an app does and checks that every `Prove` form compiles there and every removed or hidden name does not.
**Depends on:** SwiftFormal, and SFProve, which it re-exports (`@_exported import`), so a test target needs one product for walks and symbolic proofs (the owner's decision). **Must not depend on:** any other engine module (SFSIL, SFVerifyKit and so on).
**Fast loop:** `Scripts/sandbox.py SwiftFormalTesting` (about 14 s). **Connected loop:** `Scripts/sandbox.py SwiftFormalTesting --connect` (same commands today, see Known gaps)
**Real consumers:** none yet. Anyone who writes a Swift Testing suite with `SwiftFormalTesting` is the real consumer.
**Platforms (verified):** macOS, iOS (`xcodebuild -scheme SwiftFormalTesting -destination 'generic/platform=iOS Simulator' build` succeeds). The trap walk (`TrapWalk.swift`, `TrapWalkProtocol.swift`, the exit tests of `NoTrap.swift`) uses exit tests and is compiled only on macOS and Linux; Linux is not run here. `Prove(neverTraps:)` exists everywhere and records a warning where exit tests do not.
**Known gaps:** no consumer command in the registry; [`Examples/Walk`](../../Examples/Walk) uses it, and its own tests are the check. Tests were not run on an iOS simulator.
